# MY FIT — Personal 3D Select Shop

2026-11-08 로컬 구현. 기존 앱과 같은 데이터·라우트를 사용하는 기능 확장이다. 포토리얼리스틱한 완성 제품 모델이나 실측 피팅 서비스가 아니라, 조작 가능한 매장과 종류별 3D 템플릿을 제공한다.

## 실행과 조작

- 별도 설치/빌드 없이 HTTP 정적 서버로 실행한다. `file://`에서는 ES modules와 공개 데이터 로딩이 작동하지 않는다.
- 저장소 안: `python -m http.server 8095 --bind 127.0.0.1`, `http://127.0.0.1:8095/#shop`.
- 부모 디렉터리에서 실행하면 `/my-fit-pages-repo/#shop` 하위 경로를 쓴다. 실제 검증은 이 방식으로 진행했다.
- 스크롤로 입장, WASD/방향키로 걷기, 배경 드래그로 시점 변경, Esc로 이동 입력 해제/패널 종료. 모바일은 왼쪽 아날로그 조이스틱과 배경 드래그를 쓴다.
- 하단 5개 구역 버튼으로 바로 이동할 수 있다. 상품 목록에서 피팅을 선택하고, 피팅룸에서 앞/옆/뒤/45도 회전, 확대/축소, 드래그 회전을 쓴다.
- 피팅 중에는 360도 확인을 위해 시야를 가리는 벽을 숨기는 단면 보기로 전환한다. 매장 보행으로 돌아오면 벽과 이전 위치·방향을 복원한다.
- 일반 보기 링크와 기존 데스크톱/모바일 메뉴의 3D 매장 버튼으로 양쪽 화면을 오간다.

## 파일 구조

| 파일 | 역할 |
|---|---|
| `entry.mjs` | 라우트별 지연 로딩, 하나의 앱 인스턴스, WebGL 실패 대체 화면 |
| `shop.mjs` | 상태·입력·DOM UI, 보행/피팅 카메라, 기존 앱 연결, 저장/다운로드 |
| `core.mjs` | 충돌, 입장 경로, 품목 매핑, 저장 검증, 최신 선택 보장, 향수 메타데이터 비교 |
| `world.mjs` | 하나로 연결된 매장, 문, 랙, 가구, 대표 상품 전시, 텍스처 해제 |
| `garments.mjs` | 중립 마네킹과 종류별 실제 3D 메시. 처음 의상 전시/피팅 시 지연 로드 |
| `catalog-support.json` | 현재 공개 66개 품목의 매핑 감사 자료. 실제 런타임은 로컬 수정 품목으로 다시 계산 |
| `ai-preview.mjs` | 비활성 실사 AI 확장 인터페이스. 공급자·키·업로드·네트워크 호출 없음 |
| `shop.css` | DOM 접근성·반응형 UI·모션 감소 |
| `vendor/` | Three.js 0.180.0 모듈과 MIT 라이선스 |

기존 `app.js`에는 라우트, 읽기 중심의 `MyFitBridge`, 품목 갱신 이벤트만 연결했다. DB 이름·스키마는 변경하지 않았다. 상품 편집·사진 갤러리·기존 진열 편집·기존 추천·사진 업로드·실제 착장 기록은 원래 UI를 사용한다.

## 재현 수준과 제한

현재 공개 옷장: PRODUCT_BASED 0 / APPROXIMATE 52 / UNSUPPORTED 14.

착용 미지원 14개 중 향수 6개는 코디 메타데이터로 사용할 수 있다. 나머지 아이웨어·반지·시계·넥타이 등 8개는 사진/상세만 제공한다. 모든 품목은 전체 상품 목록에 남는다.

티셔츠, 긴팔, 셔츠, 니트, 베스트, 후디, 재킷, 봄버, 블레이저, 코트, 스트레이트/와이드/벌룬/반바지, 스니커즈/청키/더비/로퍼, 모자, 가방 템플릿을 사용한다. 개별 상품의 로고·패턴·실측·봉제·원단 움직임·정확한 뒷면을 재현하지 않는다. 리버서블은 하나의 소유 ID에 두 착용 면을 연결한다.

중립 성인 남성, 고정 포즈, 기본 이너웨어 유지. 사용자 얼굴, 자동 신체 측정, 체형 변경, 스킨 리그·포즈 변경, 천 시뮬레이션, 실제 사이즈 적합성 판정은 제공하지 않는다. 중간 레이어는 셔츠/니트/베스트 중 하나다. 자유로운 모든 실루엣 조합의 관통 방지를 보장하지 않으며 대표 검증 조합의 소매·몸통 여유만 보정했다.

향조가 등록되어 있지 않으면 정보 부족을 표시한다. 추천 순서는 기존 계절·분위기·등록 태그/메모 비교이며 지속력·발향을 생성하지 않는다. 병은 제품별 3D 모델이 아닌 일반형 전시품이다.

## 저장과 개인정보

- 기존 IndexedDB `myfit-closet-db` 및 기존 localStorage 키를 그대로 유지한다.
- 가상 코디는 `myfit-shop3d-virtual-v1` localStorage에 별도 저장: `type=virtual`, 품목 ID, 슬롯, 착용 면, 모델 버전, 재현 수준, 품목 지문, 향수 ID, 이름·날짜.
- 원본 이미지/얼굴/신체 정보는 가상 코디에 복제하지 않는다. 최대 100개, 백업 입력 최대 512KB.
- 3D 코디 백업·복원은 가상 코디만 포함한다. 동일 ID는 기존 저장을 보존하며 합친다. 사진/실제 착장 기록은 기존 앱 백업을 쓴다.
- 저장 오류는 실패로 표시하고 성공 알림을 내지 않는다. 품목 수정 시 오래된 피팅을 해제하고, 삭제된 품목은 복원 시 제외한다.
- 실제 착장 기록은 사용자가 명시적으로 버튼을 눌러 원래 기록 폼을 연 후 저장해야 한다. 가상 저장 자체는 착용 횟수를 바꾸지 않는다.
- 신규 외부 API·웹캠·AI 전송·과금 호출이 없다. 기존 Google Fonts, 사용자가 누르는 Open-Meteo 날씨 조회 등 기존 동작은 유지된다.
- STOCKTOON LITE, Vercel, Supabase 설정을 수정하지 않았다.

## 자산 출처

- Three.js **0.180.0**, [공식 프로젝트](https://github.com/mrdoob/three.js/tree/r180), MIT. `vendor/THREE-LICENSE.txt` 포함. 두 고정 버전 모듈을 jsDelivr npm 배포본에서 가져왔으며 런타임 CDN 요청은 없다.
- 매장·가구·문·마네킹·의상: 프로젝트에서 작성한 절차적 geometry. 외부 구매 모델 없음.
- 우드 무늬·간판: 소형 CanvasTexture. 반복 우드 슬랫은 InstancedMesh.
- 상품 사진: 기존 보유품 사진 재사용. 원본/AI 보정 표시와 출처는 기존 상세 UI에 유지. 새로운 개인 사진이나 대량 이미지 컬렉션을 추가하지 않았다.
- Blender 실행 파일과 `1000031410.mp4` 원본을 작업 공간에서 찾지 못했으므로 사용했다고 주장하지 않는다.
- GSAP·GLTFLoader는 도입하지 않았다. 네이티브 스크롤로 동일 카메라 경로를 제어하고 의상은 로컬 코드에서 생성하므로 이 기능에는 필요하지 않다.

## 검증

`node tests/shop3d.mjs`: 13개 테스트 그룹. 66개 지원 상태, 모든 지원 메시의 유한 좌표·입체 부피, 형태별 차이, 기본 몸 보존, 충돌과 입장 연속성, 늦은 이전 모델 폐기, 로딩 실패 시 직전 상태 유지, 별도 저장, 백업/용량 오류, 수정·삭제, 향수 메타데이터, 기존 라우트 속성과의 충돌 방지.

기존 테스트 6개도 모두 통과했다:

```text
node tests/wardrobe-and-references.cjs
node tests/model-looks.cjs
node tests/curated-wardrobe.cjs
node tests/room-editor.cjs
node tests/room-scenes.cjs
node tests/reference-edit.cjs
```

브라우저 검증 도구는 `tests/shop3d-fixture.html`과 `tests/shop3d-routes.html`이다. 로컬 호스트에서만 작동한다. 첫 도구는 공개 품목 복사본과 메모리 저장소를 사용해 실제 사용자 DB 없이 컨텍스트 손실·복원, WebGL 미지원, 모션 감소, 저장 오류, 사진 404, 품목 수정·삭제를 재현한다. 두 번째 도구는 실제 앱을 iframe으로 열어 직접 경로와 로딩 모듈을 표시한다.

브라우저에서 다섯 구역 간 직접 보행, 중앙 가구 충돌, 드래그 시점, 조합 3개 이상, 앞·옆·뒤, 양면, A/B, 향수 추가/제거, 저장·새로고침 복원, JPEG 다운로드, JSON 백업 병합, 실제 기록 초안 연결, 기존 사진 갤러리, 360/390/430px·가로 화면을 확인했다. 2D/3D 3회 전환 후 canvas 1개, 피팅 회전 버튼 정상. 기존 직접 경로는 CSS와 931바이트 진입 모듈만 읽고 Three.js/매장/의상 모듈은 읽지 않았다.

검증하지 않은 범위: 실제 휴대폰 하드웨어와 두 손가락 동시 입력, 실제 저속 통신망, 브라우저별 장기간 메모리 안정성. 느린 모델 요청의 순서 역전은 실제 네트워크 대신 지연 Promise 단위 검증을 했다. 전체 보유품의 모든 가능한 레이어 조합을 시각 검증한 것은 아니다.

## 성능과 운영

Windows의 앱 내 Chromium에서 1280×720, DPR 1.25, 그림자 켜짐 기준으로 보행 중 1초 단위 관찰값 52–60fps, 대표 피팅 60fps. 390px 모바일 크기에서는 조이스틱 보행 56–58fps를 관찰했다. 실제 휴대폰 성능 수치나 보장값은 아니다. 초기 로딩·리사이즈 순간은 별도이며 전체 벤치마크 평균도 아니다.

신규 3D 폴더는 약 0.85MB(감사 JSON·문서 포함, 압축 전), 실행 모듈은 약 0.79MB다. gzip 합계는 약 0.22MB 추정이며 실제 서버 압축 협상 측정값은 아니다. 현재 manifest가 참조하는 기존 옷장 JSON은 약 10.73MB, 보관된 이전 JSON까지 포함한 data 폴더 전체는 약 15.30MB, 기존 assets는 약 9.77MB다. 모두 신규 3D 용량과 별개이며 변경하지 않았다. 기존 앱 데이터 준비 시간이 입장 대기 시간에 포함된다.

DPR 최대 1.5, 모바일 최초 로드 시 실시간 그림자 기본 OFF, 설정으로 변경 가능. 2D 보기·탭 숨김·컨텍스트 손실에서는 렌더 루프를 정지한다. 전시 사진은 GPU용 소형 텍스처로 변환하고 이전 텍스처/메시/재질은 교체할 때 해제한다. 실시간 거울 반사 대신 금속 패널과 별도의 아바타 확인 카메라를 사용한다.

이번 변경은 별도 로컬 브랜치에서만 작업했다. 원격 push·PR 생성·GitHub Pages 배포는 실행하지 않았다. 향후 승인 후 기존 정적 호스팅 방식으로 전체 파일을 배포하면 되며 Vercel/Supabase나 추가 서버가 필요하지 않다. 기존 사용자 데이터는 브라우저 origin에 있으므로 로컬과 공개 사이트가 자동 동기화되지는 않는다.

정밀 모델링·포토리얼리스틱한 상품 재현, 체형/리그, 실사 AI 공급자 및 서버 연결은 별도 작업 범위다. 유료 자산이나 계정이 없어도 현재 기본 매장·피팅은 동작한다.
